# 쿼터뷰·직접 드롭·골드 도박

2026-09-10 초안. 아래 확률·가격·횟수는 플레이테스트로 조정하는 제안이다.

## 1. 쿼터뷰

고정된 비스듬한 위 시점으로 바닥과 캐릭터의 앞/옆면을 함께 보여준다. 2D 스프라이트와 마름모 바닥으로 구현하며 실제 3D 모델, 카메라 회전, 다층 높이 이동은 초기 제외한다. 전체 미술은 쿼터뷰 기준으로 통일하고 정면 캐릭터에 바닥만 기울이는 방식은 최종 에셋에 사용하지 않는다.

바닥 타일은 64×32의 2:1 마름모를 기준으로 한다. 맵 데이터의 논리 좌표 `(u,v)`는 화면/월드 좌표로 `x=(u-v)×32`, `y=(u+v)×16` 변환한다. 역변환은 `u=x/64+y/32`, `v=y/32-x/64`다. 이 변환은 타일 배치/선택에 사용한다. 실제 CharacterBody2D와 충돌은 투영된 Godot 월드의 바닥 평면 좌표에서 처리하여 두 물리 좌표계를 섞지 않는다.

- WASD는 화면 기준 상하좌우로 움직인다. 대각 입력은 정규화한다.
- 마우스 화면 좌표를 카메라 역변환해 같은 월드 공간의 조준점으로 만든다.
- 캐릭터 위치는 발밑 피벗이다. 몸체 그림은 위로 오프셋하며 발밑 충돌과 표시용 몸체를 구분한다.
- Y 정렬은 발밑 기준으로 한다. 벽/기둥은 가림 단위를 분리하고 캐릭터를 가리면 투명도 또는 실루엣으로 표시한다.
- 투사체 논리 위치와 그림의 높이 오프셋을 분리한다. 높은 위치에서 그려져도 바닥상의 동일 궤적으로 적중한다. 보스 장판은 실제 충돌 범위와 일치해야 한다.
- 그림자·드롭·몸체·공중 VFX의 정렬 규칙을 명시한다. 장비 드롭 라벨은 UI에서 월드 위치를 투영해 표시한다.

첫 검증 장면은 마름모 바닥, 기둥 2개, 적 1마리, 투사체 하나로 구성한다. 카메라 이동/창 크기 변경에서도 조준 일치, 기둥 앞뒤 정렬, 대각 속도, 드롭 클릭/획득 위치를 확인한 뒤 맵을 확장한다.

## 2. 필드에서 장비와 젬 직접 획득

획득 경로는 전투 드롭, 골드 가차, 기본 젬 확정 구매, 중복 조각 교환이다. 장비뿐 아니라 주스킬 젬과 보조 젬도 적에게서 떨어진다. 자동으로 가차 화면에 보내지 않고 바닥에 실제 드롭 오브젝트로 보여준다.

| 처치 대상 | 장비 판정 | 젬 판정 | 규칙 |
|---|---:|---:|---|
| 일반 적 | 2% | 0.5% | 각각 독립 판정, 둘 다 나올 수 있음 |
| 정예 | 15% | 5% | 각각 독립 판정 |
| 스테이지 보스 | 100%로 1개 | 25%로 1개 | 장비 최소 1개 보장 |

드롭된 젬은 초기 주스킬 40%, 보조 60%로 구분한다. 후보 풀을 검증한 뒤 등급과 ID를 판정한다. 주/보조 각 개방 풀은 모든 선택 가능한 등급에 유효 항목이 있어야 한다. 데모의 미구현 등급은 별도 명시한 데모 테이블로 제외한다.

드롭 발생 확률과 희귀도 확률은 별개다. 초기 조건부 희귀도 표:

| 출처 | 일반 | 마법 | 희귀 | 영웅 | 전설 | 신화 |
|---|---:|---:|---:|---:|---:|---:|
| 일반/정예 | 65% | 25% | 8% | 1.8% | 0.19% | 0.01% |
| 보스 | 40% | 35% | 20% | 4.4% | 0.55% | 0.05% |

각 행 합계 100%. 장비의 영웅 고유 하위 풀 비중 20%, 전설/신화 100% 규칙은 경제 문서와 공유한다. 특정 보스의 특정 고유 가중치는 같은 등급 안의 대상 분포를 바꾼다. 등급 전체 확률까지 올리는 경우 별도 표로 명시한다. 드롭은 가차 천장 카운터를 변경하지 않는다.

예: 일반 적 한 마리가 신화 장비를 줄 확률은 `2%×0.01%=0.0002%`다. 특정 신화 장비는 해당 풀 내부 가중치를 더 곱한다. 보스 파밍은 확정 장비와 더 나은 등급 분포로 일반 적과 구별한다.

일반 적 80, 정예 3, 보스 1마리인 예시 한 판의 기대 획득량은 장비 3.05개, 젬 0.8개다. 이는 실제 스테이지 구성 확정 전 경제 검산용이다. 판매 골드까지 포함해 기존 평균 120골드/판 목표와 함께 재조정해야 한다.

## 드롭 표시·중복·저장

- 등급 색/이름/아이콘과 획득 소리를 사용한다. 전설 이상은 눈에 띄는 기둥 효과를 더한다.
- 가까이 가면 장비/젬을 획득하고 젬 중복은 기존 조각 정책으로 변환한다. 젬도 주워야 소유/변환이 확정된다.
- 초기 필터는 등급별 라벨 표시 조절만 제공하고 자동 폐기하지 않는다.
- 방 종료 때 남은 드롭은 결과/미수령 목록으로 모아 누락을 막는다. 인벤토리 초과는 기존 미수령 정책을 적용한다.
- 처치 ID → 드롭 결과 → 획득/조각 전환을 추적한다. 동일 드롭 ID는 한 번만 획득한다.
- 방 도중 비정상 종료는 방 시작 스냅샷으로 돌아간다. 전리품 RNG는 전투/시각효과 RNG와 분리하며 방 seed와 고정 encounter/spawn ID로 결과를 재현해 단순 종료 재추첨을 막는다.

## 3. 골드 도박: 헤르메스의 동전

스테이지의 방 사이 안전 구간에 등장하는 선택 이벤트다. 장비/젬을 뽑는 가차와 달리 골드를 걸고 골드를 받는다. 현금 구매·환전·외부 거래는 없다.

베팅 재원은 **이번 출격에서 번 미정산 골드**로 제한한다. 이전 출격에서 저장한 보유 골드는 자동 사용하지 않는다. 이번 출격 골드를 모두 걸어 잃을 수 있고, 다시 전투로 모을 수 있다. 출격 비용과 필수 수리비가 없으므로 골드 0으로도 계속 플레이 가능하다.

한 출격에 이벤트 1회, 이벤트 안에서 최대 3번 베팅. 베팅 최소 10골드, 10골드 단위. UI에 직접 금액 선택과 절반/전부를 제공하며 전부 선택은 잔액 이하의 가장 큰 10 단위다. 기본 선택은 최소 금액이며 마지막 베팅 금액을 자동 재사용하지 않는다.

| 결과 | 확률 | 총 지급액 |
|---|---:|---:|
| 실패 | 60% | 베팅액 ×0 |
| 적중 | 30% | 베팅액 ×2 |
| 대박 | 10% | 베팅액 ×3 |

총 지급액에는 원금이 포함된다. 100골드를 걸면 실패 -100, 적중 순이익 +100, 대박 순이익 +200이다. 기대 총 반환은 `0.6×0+0.3×2+0.1×3=0.9`, 즉 평균 순손익 -10%. 무한 골드 생산 수단 대신 순간적인 큰 보상의 선택지로 둔다. 확률·총 지급액·현재 잔액·남은 횟수를 실행 전에 표시한다.

도박 획득금도 미정산 골드로 남는다. 이후 사망 시 기존 50% 정산 규칙을 동일하게 적용한다. 베팅으로 잃은 금액은 사망 정산에서 되살리지 않는다. 다음 판에서 재도전할 수 있으며 연속 실패에 따라 몰래 확률을 바꾸지 않는다.

## 도박 저장 경계

도박은 반드시 방 클리어 후 안전 체크포인트에서만 연다. 진입 시 미정산 보상과 완료 방을 저장한다. 베팅은 지불·결과·남은 횟수·RNG 상태·미정산 골드를 하나의 새 체크포인트 revision에 저장하고 성공 뒤 결과를 보여준다.

재접속은 최신 안전 체크포인트를 사용하므로 이전 전투 방으로 복귀해 손실을 취소하지 않는다. 저장 실패면 베팅 전체 취소, 성공 후 연출 중 종료면 저장된 결과를 유지한다. 완료 명령 ID로 중복 클릭 지급을 막는다. 파일 자체를 사용자가 되돌리는 오프라인 조작까지 방지한다고 주장하지 않는다.

## 4. 추가 컴포넌트와 개발 순서

- IsoMapProjection: 타일 좌표 투영/역변환. InputController는 카메라 변환, Presentation은 피벗/Y 정렬을 담당한다.
- DropResolver: 적 유형·지역·개방 풀 → 드롭 인스턴스. LootService와 같은 가중치 선택기를 재사용하되 출처별 테이블은 분리한다.
- PickupService: 거리·공간·획득 ID 검증, 젬 중복 처리, 미수령 목록 전달.
- GoldGambleService: 베팅 조건/확률/손익 계산. application 명령이 SaveRepository를 통해 체크포인트까지 함께 저장한다.
- RunState 추가: gamble_event_id, attempts_remaining, gamble_rng_state, completed_room_id, dropped/picked IDs. 도박 계산은 UI 코드에 넣지 않는다.
- 데이터 추가: drop_tables.json, gamble_rules.json. 고유 하위 풀과 아이템 생성 규칙은 가차와 공유한다.

구현 순서는 쿼터뷰 전투 → 장비/젬 직접 드롭 → 경제/저장 → 도박이다. 도박은 첫 전투 완성을 지연시키지 않는 후순위 기능으로 둔다.

검증: 좌표 왕복, 깊이 정렬, 각 확률 합계, 장비/젬 동시 드롭, 중복 획득 거부, 보스 장비 보장, 베팅 기대값, 0골드 재출격, 잔액 부족/3회 초과 거부, 도박 저장 실패/성공 후 강제 종료, 방 체크포인트 복귀와 RNG 재현.
