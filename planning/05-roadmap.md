# 개발 단계와 완료 기준

## P0: 기술 기반

엔진 버전 고정, 실행 가능한 Godot 프로젝트, 입력/화면/씬 전환, 정의 데이터 검증기. Windows에서 빈 프로젝트를 실행하고 내보낸 실행 파일이 네트워크 없이 동작하면 완료.

## P1: 전투 프로토타입

쿼터뷰 바닥, 발밑 피벗, 카메라 조준 변환, 기둥 가림 처리를 먼저 검증한다.

도형 캐릭터 이동/회피, 벼락 투사체, 근접 몹, 체력/사망. 이동 중 조준, 고속 투사체 충돌, 같은 적 중복 적중 제한, 죽은 적 공격 취소를 확인한다. 낮은 렌더링 FPS에서도 공격 횟수와 쿨다운이 일관되어야 한다.

## P2: 빌드 시스템

레벨·능력치 계산과 보조 슬롯 Lv.1/5/15/30 개방을 추가한다. 데모는 Lv.10까지 플레이하며 높은 레벨 경계는 자동 검증한다. 계수 변경과 무료 재분배가 저장·표시·실제 전투에 일관되게 적용되어야 한다.

주스킬 3종, 보조 5계열, 장비 3슬롯, 희귀 변형 샘플. 피해 계산의 가산/곱산·저항·치명타 경계, 호환 태그, 같은 계열 중복, 발동 재귀 제한을 자동 검증한다. 최소 3개 조합이 실제 공격 형태를 다르게 보여야 한다.

## P3: 경제와 저장

필드 장비/젬 드롭과 획득 중복 방지를 구현한다. 선택형 골드 도박은 기본 경제 저장이 통과한 뒤 안전 체크포인트에서 추가하고 종료 후 손실 취소/중복 지급을 검증한다.

가차, 확정 구매, 중복 조각, 장착/판매, 복구 가능한 저장. 동일 seed의 재현, 50회 천장 경계, 지불 실패, 빈 풀, 가득 찬 인벤토리, 중복 명령을 검증한다. 확률은 100만 회 정도의 고정 seed 표본과 통계 오차 범위로 점검하며 정확한 비율 일치를 요구하지 않는다. 천장 적용 전/후를 분리한다.

파일 쓰기 실패·교체 직전 종료·손상 파일·구버전 파일을 주입해 골드만 사라지거나 보상이 복제되지 않는지 확인한다. 프로세스 강제 종료 후 체크포인트 재개도 검증한다.

## P4: 첫 플레이 가능 버전

공통 스토리 장면 재생기를 구현하고 출항 오프닝을 연결한다. 임시 그림으로 넘김·건너뛰기·재접속을 검증한 뒤 최종 그림을 적용한다.

해안 3스테이지, 적 3종, 보스, 최소 모션과 SFX, 거점. 15분 플레이 루프를 확인하고 부하 장면에서 프레임 시간과 저장 지연을 기록한다. 이 단계까지를 우선 제작 범위로 한다.

## P5: 캠페인·엔드게임 확장

귀환 엔딩과 이타카 거점 전환을 연결한다. 완료 보상은 엔딩 전에 저장하고, 재생/다시 보기로 보상이 중복되지 않는지 확인한다.

액트 2~5를 한 번에 양산하지 않고 먼저 캠페인 완료 플래그와 이타카 거점 → T1 항로의 전환을 임시 콘텐츠로 검증한다. 그 뒤 지역별 에셋과 보스, 상위 희귀 콘텐츠, T1~T10을 점진적으로 채운다.

## 변경 시 지켜야 할 문서 규칙

데이터 필드 변경은 기술 문서와 세이브 마이그레이션을 같이 수정한다. 가격/확률 변경은 경제 문서와 실제 데이터 테이블을 같이 수정한다. 에셋 추가는 manifest를 갱신한다. 구현되지 않은 기능을 README에서 완료로 표시하지 않는다.

## 현재 상태

Godot 4.7.2 프로젝트와 P1 전투 아레나 일부를 구현했다. 피해/충돌/좌표 단위 검증과 headless 실행을 확인했다. 그래픽 화면의 실제 조작 검수, 배포 export, 기둥 충돌/가림, 최종 에셋, 성능 측정은 남아 있어 P0/P1 전체 완료로 보지 않는다.
